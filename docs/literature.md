# Поиск метаданных и импорт библиографии

Клиенты возвращают **кандидатов**. Ни запись Crossref/OpenAlex, ни наличие аннотации,
ни ссылка на PDF не подтверждают чтение источника. Импорт не редактирует
`sources.jsonl`, не ставит `metadata_verified=true` и не создаёт научных утверждений.

## Crossref и OpenAlex

```bash
sci-writer search-crossref runs/article --query "искомая тема" --rows 20
sci-writer search-openalex runs/article --query "искомая тема" --rows 20 --language ru
```

OpenAlex использует реальный `GET https://api.openalex.org/works` с `search`,
`per-page` и необязательным фильтром языка. Поддержан один запрос первой страницы,
до 100 результатов; курсорный сбор всей базы не выполняется. API-ключ берётся
CLI из переменной `OPENALEX_API_KEY` или переменной с именем из `--api-key-env`.
Само значение ключа не передаётся аргументом командной строки и не пишется в лог.
Клиент посылает ключ только в `Authorization: Bearer`, без него делает базовый запрос.

Согласно [актуальной документации аутентификации OpenAlex](https://help.openalex.org/api/authentication/),
проверенной 21.11.2026, небольшие запросы допускаются без ключа; масштабирование и
курсорная пагинация требуют учёта ключа, бюджета и лимитов. Лимиты меняются, поэтому
фиксированное обещание «100 запросов/с» отсутствует. Код не создаёт аккаунт и не
запрашивает ключ отправкой письма. При HTTP 401/403/429 сохраняется явная ошибка,
а успешный поисковый отчёт не создаётся.

Из [полей Work OpenAlex](https://help.openalex.org/api/llm-quick-reference/)
сохраняются название, авторы, год, журнал, библиографические поля, DOI/OpenAlex ID,
аннотация из inverted index, ссылка на открытый PDF при наличии и признаки отзыва
публикации. PDF автоматически не скачивается. Кроссреф-клиент также сохраняет
журнал, том, номер, страницы, издателя, ISBN/ISSN и аннотацию, если они возвращены API.

Результаты и исходный JSON сохраняются в `search/`; в `search-log.jsonl` — запрос,
провайдер, время, SHA-256 исходного ответа и путь к кандидатам. Идентификатор
`cand_<hash>` детерминирован по DOI либо библиографическому набору. Никаких S-ID
до включения источника в проверенный каталог не назначается.

Оба клиента используют фиксированные HTTPS endpoints, таймаут и предел размера
ответа. Redirects и прокси из переменных окружения отключены. Произвольный URL из
найденной записи не становится новой командой для HTTP-запроса.

## Локальный BibTeX/RIS

```bash
sci-writer import-bib runs/article private/export.bib
sci-writer import-bib runs/article private/export.ris
# Для фактического экспорта в Windows-1251:
sci-writer import-bib runs/article private/export.ris --encoding cp1251
```

Файл должен быть законно получен пользователем: ручной экспорт из каталога,
менеджера библиографии, eLIBRARY/РИНЦ, РГБ или другого разрешённого источника.
Команда не скрейпит сайты и не обходит их условия доступа. Использование имени
каталога в документации не означает наличие автоматического подключения к нему.

Поддерживаются UTF-8/BOM по умолчанию и явная иная кодировка, BibTeX с вложенными
скобками, строковыми макросами и конкатенацией, корпоративные авторы в фигурных
скобках, многострочные RIS-поля. Метаданные и исходное представление сохраняются
для последующей проверки. Дубликаты DOI внутри одного импорта не размножаются.
Записи с отсутствующим годом/автором/URL остаются неполными кандидатами.

Неопределённые BibTeX-макросы, повторные поля/ключи, незакрытые записи и `crossref`
наследование отклоняются с объяснением: экспортируйте полные самостоятельные записи.
`@preamble` и `@comment` следует удалить перед импортом; они не исполняются.
Неизвестные TeX-макросы в строках остаются буквальным текстом с предупреждением.
Это ограниченный безопасный парсер экспорта, а не интерпретатор всего языка BibTeX.

## После получения кандидатов

1. Сопоставить запись с издательской или каталожной карточкой; проверить точное
   издание, состав авторов, год, страницы, отзыв/исправление публикации.
2. Решить, подходит ли работа исследовательскому вопросу и истории научной школы.
3. Получить разрешённый текст, записать реальный уровень доступа и прочитанные страницы.
4. Включить запись в `sources.jsonl` с S-ID и свидетельством проверки.
5. Только затем создавать C-утверждения с локаторами и областью применимости.

Тесты библиографического кода используют явно искусственные записи и HTTP mock.
Они проверяют форматы и отсутствие ложного прочтения, но не измеряют полноту
реальных каталогов и не воспроизводят API-квоты.
