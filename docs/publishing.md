# Издательские метаданные и форматы

В v0.2 русская научная школа связана с машиночитаемым издательским блоком и
библиографией. Форматирование не изменяет научную готовность: её определяют
доказательства, реальные проверки и рецензенты.

## Что проверено по стандартам

На 21.11.2026 официальный портал Росстандарта показывает действующими
[ГОСТ Р 7.0.7-2021](https://protect.gost.ru/gost/details/b9a644c2-9661-41d4-ada0-49950eb69d8b)
об издательском оформлении статей и
[ГОСТ Р 7.0.5-2008](https://protect.gost.ru/gost/details/2eef7820-44bc-49a4-bf1f-fe51c54039dc)
о библиографических ссылках. Первый адресован издателям и выпускающим организациям;
он не превращает все реквизиты опубликованной статьи в обязательный вход рукописи.

Автоматический профиль `gost-r-7.0.5-2008` — практический формат распространённых
статей, книг и глав с проверкой редактором. Это не заявление о полном нормативном
соответствии всех возможных видов источников. Журнал может требовать иной порядок,
пунктуацию, транслитерацию, отдельный англоязычный References или шаблон Word.
Для сетевых документов дополнительно проверьте применимость ГОСТ Р 7.0.108-2022.

УДК, ГРНТИ, DOI, EDN, ORCID, SPIN вводятся по проверенным данным. EDN/DOI новой
статьи нельзя выдумывать до их назначения. Код научной специальности ВАК не равен
УДК. Авторство, степень, аффилиация, финансирование и вклад требуют подтверждения
автором; пустое поле не означает «нет финансирования» или «нет конфликта».

## Метаданные статьи

Опциональный объект `brief.publication` проверяется по
`schemas/publication.schema.json`. Пустой объект допустим на этапе постановки
работы. Перечень реквизитов для подачи задаётся конкретным журналом через
`journal-profile.publication_required_fields`, например `title.ru`, `title.en`,
`abstract.ru`, `abstract.en`, `keywords.ru`, `keywords.en`, `authors`.

| Поле | Содержание |
|---|---|
| `title`, `abstract` | Объекты `{ "ru": "…", "en": "…" }` |
| `keywords` | Объект с массивами терминов `ru` и `en` |
| `authors` | Авторские имена RU/EN, `affiliation_ids`, степень, звание, ORCID, SPIN, email, вклад |
| `affiliations` | Уникальный `id`, названия организации, города и страны RU/EN |
| `udc`, `grnti`, `doi`, `edn` | Только известные и проверенные идентификаторы |
| `funding`, `conflicts`, `acknowledgements`, `author_contributions` | Отдельные тексты RU/EN |
| `citation_style` | `gost-r-7.0.5-2008` (по умолчанию) либо `numeric` |
| `reference_overrides` | Проверенная редактором полная запись для конкретного `S001` |

### Совместимость с `publication_meta`

Руководство по v0.2 использует имя `publication_meta`. Оно поддерживается как
псевдоним `brief.publication` **с той же структурой** по `publication.schema.json`:
например, `publication_meta.title.ru` и `publication_meta.abstract.en`. Отдельной
плоской схемы метаданных нет.

- Пустое `publication: {}` из `init` не скрывает заполненный `publication_meta`.
- Если заполнен только один блок, используется он; одинаковые непустые блоки допустимы.
- Разные непустые блоки отклоняются до вызова языкового сервиса и до экспорта.
  Оставьте один блок либо согласуйте значения; после изменения повторите проверки.

Общий resolver применяется при валидации, проверке английской аннотации, сверке
сырых отчётов, рендеринге шапки и сборке манифеста. Исходный `brief.json` не
переписывается и целиком участвует в хешах качества и рецензий. Изменение любого
из двух полей после рецензирования делает зависимые этапы устаревшими. Сборщик
не переносит новые метаданные в уже одобренную рукопись обновлением старого хеша.

Поля автора: `name_ru`, `name_en`, `affiliation_ids`, `degree_ru/en`,
`academic_title_ru/en`, `orcid`, `spin`, `email`, `corresponding`,
`contribution_ru/en`. Проверяется существование всех указанных аффилиаций.
Синтаксическая проверка идентификатора не подтверждает, что он принадлежит человеку.

Издательский блок выводит только заполненные поля. Редактор проверяет полноту
перевода и единство имени автора, организации и терминов в русской и английской
частях. Финансирование и авторские сведения можно переместить в конец статьи по
шаблону журнала; стандартный экспорт использует общий фронтальный блок.

## Библиография

`source.schema.json` дополнена полями `journal`, `volume`, `issue`, `pages`,
`city`, `publisher`, `edition`, `booktitle`, `article_number`, `page_count`,
`editors`, `isbn`, `issn`, `edn`, `accessed_at`, `language`. Все они опциональны:
наличие DOI не заменяет страницы, а отсутствие DOI не делает книгу непригодной.

Рендерер сохраняет порядок появления ссылок, строит цифровые отсылки и выводит
журнал/том/номер/страницы, издательство/город/издание, DOI/EDN, URL/дату обращения,
если они известны. Год не указан — явно `б. г.`, неизвестные реквизиты не добавляются.
Полный BibTeX содержит те же известные выходные данные. Для диссертации без
проверенного вида степени не назначается автоматически тип `phdthesis`.

При специальном стиле журнала `reference_overrides.S001` заменяет одну запись
готовой проверенной строкой. Такая правка — часть `brief`, поэтому сбрасывает
зависимые проверки. Полная CSL-интеграция, автоматическая транслитерация и каталог
шаблонов журналов не заявляются реализованными.

### Выбор стиля при сборке

```bash
sci-writer finalize runs/article --bibliography-style gost
sci-writer finalize runs/article --bibliography-style generic
```

CLI-имя `gost` соответствует `citation_style: "gost-r-7.0.5-2008"`, а `generic` —
`citation_style: "numeric"`. Без флага используется проверенное значение из
издательского блока; при его отсутствии — ГОСТ-ориентированный профиль.

Для `reviewed_manuscript` с `ready_for_submission=false` флаг разрешает механически
собрать альтернативный стиль, сохраняя все доказательства, отсылки и рецензии.
`brief`, состояние этапов и отчёты при этом не изменяются. При
`ready_for_submission=true` запрос другого стиля отклоняется **до сборки**:
сначала вручную измените `citation_style` в выбранном блоке `brief.publication`
или `brief.publication_meta`, затем заново выполните зависимые проверки и рецензии.
Совпадающий с уже проверенным стилем флаг допустим. Проверки готовности и семи
этапов выполняются независимо от этого аргумента.

Манифест записывает `citation_format` (фактический стиль) и `bibliography_style`
с полями `requested`, `configured`, `effective`, `override_applied` и
`reference_overrides_priority`. Уже проверенные `reference_overrides.S001` имеют
приоритет над общим стилем: флаг не перезаписывает редакторскую запись источника.

## DOCX и LaTeX

```bash
pip install -e '.[publishing]'
sci-writer finalize runs/article --formats docx,tex
# Если проверки ещё не закончены:
sci-writer export-draft runs/article --formats docx,tex
```

Markdown, BibTeX и доказательный пакет остаются основным выпуском. Дополнительные
файлы — `article.docx` и `article.tex`. Для черновика сохраняются предупреждение
о незавершённости и рабочие маркеры. Экспорт не запускает внешние сетевые сервисы.

DOCX создаётся `python-docx`: A4, поля, русская гарнитура, заголовки, таблицы,
списки, двуязычный блок. При наличии формул и установленного Pandoc используется
его sandbox-reader Markdown → JSON для отдельной формулы. Из результата берётся
только один узел Math; новый AST не содержит метаданных, ссылок на ресурсы или
raw-узлов. Writer получает этот AST и создаёт редактируемый фрагмент Word OMML,
который вставляется в основной документ python-docx. Не вызываются фильтры, TeX-компилятор, shell escape и загрузка
рисунков. При отсутствии Pandoc или неподдержанной формуле источник сохраняется
буквально с предупреждением, поэтому формулу нельзя принять за готовую вёрстку.

LaTeX-файл предназначен для XeLaTeX. Поддерживаются кириллица, базовые заголовки,
таблицы и обычные формулы с фиксированным списком математических команд. Неизвестные
TeX-команды экранируются; непонятная формула остаётся источником с предупреждением.
Автоматического выполнения TeX нет. Внешние изображения не загружаются: экспорт
сохраняет подпись и предупреждает о требуемой локальной вёрстке.

Ограничения: сложные вложенные списки, нестандартные Markdown-расширения, сноски,
сложные таблицы и журналоспецифичные колонтитулы требуют проверки. Успех конверсии
не равен визуальной приёмке: `layout_verified=false`. Предупреждения конверсии
включаются в манифест; их нельзя скрывать при заявлении готовности к подаче.

Для разработки выполнен реальный рендер тестового DOCX через LibreOffice и просмотр
PNG всех его страниц. Это проверка экспортёра на условном макете, а не автоматическое
подтверждение вёрстки будущих статей. Каждую итоговую статью следует отрендерить заново.
