# Примеры артефактов: корректный формат не равен научной готовности

Эти примеры демонстрируют текущие схемы v0.1. Они **не являются готовой статьёй, выполненным исследованием или положительной рецензией**. Намеренно показано раннее состояние: найдена реальная публикация, проверены её библиографические сведения, но содержательные утверждения и определения ещё не проверены по полному тексту. Такой пакет должен оставаться незавершённым.

Все пути относятся к одному `runs/<run_id>/`. Инициализация, установка и основной порядок команд описаны в README. Не подменяйте существующие материалы своего исследования примерами из этой страницы.

## 1. Реальный источник: только метаданные

Библиографические сведения ниже проверены 21.11.2026 по [записи PubMed, PMID 37521038](https://pubmed.ncbi.nlm.nih.gov/37521038/). Запись также даёт ссылку на [открытый полный текст PMC](https://pmc.ncbi.nlm.nih.gov/articles/PMC10382961/). Наличие ссылки не означает, что будущий агент прочитал этот текст.

Одна запись `sources.jsonl` по `schemas/source.schema.json`:

```json
{
  "id": "S001",
  "title": "GPT detectors are biased against non-native English writers",
  "authors": [
    "Weixin Liang",
    "Mert Yuksekgonul",
    "Yining Mao",
    "Eric Wu",
    "James Zou"
  ],
  "year": 2023,
  "url": "https://doi.org/10.1016/j.patter.2023.100779",
  "doi": "10.1016/j.patter.2023.100779",
  "isbn": null,
  "type": "article",
  "access": "metadata_only",
  "metadata_verified": true,
  "status": "candidate",
  "tradition": "international",
  "is_foundational": false,
  "verification_url": "https://pubmed.ncbi.nlm.nih.gov/37521038/",
  "verified_at": "2026-11-21",
  "local_path": null,
  "content_sha256": null
}
```

Здесь `metadata_verified=true` означает сверку названия, авторов, года и DOI. `access=metadata_only` описывает состояние демонстрационного реестра: полный текст ещё не зарегистрирован как прочитанный. Не повышайте доступ до `full_text` только потому, что файл можно открыть. После чтения выбранных страниц допустим `selected_pages` с настоящим `read_locator`; после полного чтения — `full_text`.

В настоящем `.jsonl` каждый объект занимает одну строку. Многострочный вид выше нужен для чтения; сериализуйте объект через `json.dumps(..., ensure_ascii=False)`.

## 2. Утверждение с незавершённой проверкой

Одна запись `evidence.jsonl` по `schemas/evidence.schema.json`:

```json
{
  "id": "C001",
  "kind": "source",
  "statement": "Найденная публикация рассматривает смещение GPT-детекторов в отношении авторов, для которых английский не является родным.",
  "verification": "unverified",
  "source_ids": ["S001"],
  "locators": {
    "S001": "Библиографическая карточка PMID 37521038: название; содержательное место в полном тексте ещё не проверено"
  },
  "scope": "Только заявленная тематика публикации. Данные, результаты и переносимость на русскоязычные научные статьи ещё не проверены."
}
```

Это честный кандидат, который нельзя использовать как подтверждённый тезис готовой статьи. Маркер `[SRC:C001]` будет отвергнут при проверке рукописи, пока `verification` не станет обоснованно `verified`. Простое редактирование статуса без чтения и точного локатора недопустимо. Кроме того, `S001` пока кандидат, а не включённый проверенный источник.

Собственный вывод хранится отдельно. Например, следующий **непроверенный кандидат вывода** не приписывается авторам публикации:

```json
{
  "id": "C002",
  "kind": "inference",
  "statement": "Применимость найденных результатов к русскому научному тексту потребует отдельной проверки.",
  "verification": "unverified",
  "source_ids": [],
  "locators": {},
  "scope": "Предварительное методическое ограничение демонстрационного проекта, не проверенный результат о русском языке.",
  "support_span": "derived",
  "depends_on": ["C001"],
  "result_ids": []
}
```

Для такого вывода используется `[INF:C002]`. Основанием inference могут быть `depends_on` с проверенными `C...`, `result_ids` с реально полученными `R...` или оба вида. Непроверенное основание не поддерживает проверенный вывод. `kind=source` не использует `result_ids`: собственный результат нельзя приписать внешней работе. Ни один пример здесь не содержит придуманного результата `R001`.

## 3. Словарь: черновое определение с видимым пробелом

`glossary.json` по `schemas/glossary.schema.json`:

```json
{
  "entries": [
    {
      "id": "T001",
      "preferred": "детектор машинного текста",
      "definition": "Предварительное рабочее понятие: программный инструмент для оценки признаков машинного происхождения текста. Это формулировка демонстрационного проекта; определение в источнике ещё не проверено.",
      "source_ids": ["S001"],
      "locators": {
        "S001": "Из названия известна тема GPT-детекторов; место определения в полном тексте не установлено"
      },
      "allowed_variants": [],
      "english_equivalents": [],
      "relations": []
    }
  ],
  "phrasebook": []
}
```

JSON структурно допустим, но **проверку тезауруса не проходит**: определение должно опираться на прочитанный текст/страницы, а `S001.access=metadata_only`. Пример специально показывает это различие. Не создавайте ложную страницу или фиктивный источник для прохождения проверки. Пустой `phrasebook` честнее «типичных научных оборотов», которых никто не извлекал из корпуса.

После предметного чтения терминолог устанавливает точное определение, контекст, локатор и отношения понятий. В реальном исследовании обязательный отечественный корпус формируется по теме; одна международная работа о детекторах не заменяет российскую научную школу.

## 4. Отсутствие собственных данных и результатов

Для демонстрационного обзора, который ещё не выполнял эмпирический анализ, `analysis/data-manifest.json` может содержать:

```json
{
  "datasets": []
}
```

А `analysis/results.json`:

```json
{
  "results": [],
  "not_applicable_reason": "Демонстрация подготовки обзора по литературе; собственные наблюдения, эксперименты и вычислительные результаты не получались."
}
```

Оба объекта соответствуют своим схемам. Они не удовлетворяют требованию эмпирической статьи с `empirical_required=true`. Для настоящего результата нужны реальные данные/план, выполненная команда, время, лог и хеши; ради примера здесь такие сведения не выдуманы.

## 5. Получение хешей

На уже созданном запуске выполните:

```bash
sci-writer hashes runs/demo
```

Поля результата используются так:

| Куда записывается | Что брать из команды |
|---|---|
| `source-audit.sources_sha256` | `sources_sha256` |
| `source-audit.evidence_sha256` | `evidence_sha256` |
| `editorial-review.manuscript_sha256` | `manuscript_sha256` |
| `editorial-review.quality_report_sha256` | `quality_report_sha256` |
| Обе peer-рецензии: `manuscript_sha256` | `manuscript_sha256` |
| Обе peer-рецензии: `review_context_sha256` | `review_context_sha256` |
| Главная рецензия: `review_context_sha256` | **`chief_context_sha256`** |

Если `quality_report_sha256` равен `null`, отчёт quality ещё не существует: нечего разбирать как выполненную проверку. Реальный хеш незавершённого файла не подтверждает его научную готовность. Изменение данных, источников и отчётов меняет review-context даже при неизменной рукописи.

## 6. Пример трёх отчётов без фиктивной независимости и выдуманных хешей

Следующий код **только печатает** демонстрационные JSON-объекты для существующего запуска `runs/demo`. Он не записывает их в рабочие отчёты и не заявляет, что рецензенты читали статью. Хеши вычисляются действующей командой, а не заменяются шаблонными 64-символьными значениями.

```bash
python - runs/demo <<'PY'
import json
import subprocess
import sys

run = sys.argv[1]
h = json.loads(subprocess.check_output(
    ["sci-writer", "hashes", run], text=True
))
dimensions = (
    "scientific_validity", "novelty", "evidence", "methods", "reproducibility",
    "russian_school", "terminology", "readability", "author_style", "journal_fit",
)
roles = (
    ("domain-reviewer", "reports/domain-review.json"),
    ("methods-reviewer", "reports/methods-review.json"),
    ("chief-reviewer", "reports/final-review.json"),
)
for role, name in roles:
    chief = role == "chief-reviewer"
    report = {
        "manuscript_sha256": h["manuscript_sha256"],
        "review_context_sha256": h[
            "chief_context_sha256" if chief else "review_context_sha256"
        ],
        "reviewer_id": "DEMO-format-only-no-independent-review",
        "reviewer_role": role,
        "independent_of_author": False,
        "decision": "major_revision",
        "issues": [{
            "id": "DEMO-001",
            "severity": "blocker",
            "location": "Демонстрационный evidence.jsonl: C001",
            "reason": "Показан только формат: содержательное основание C001 ещё не проверено.",
            "action": "Выполнить исследование, проверить источники и провести настоящую отдельную рецензию.",
            "status": "open",
            "evidence_ids": ["C001"],
        }],
        "limitations": [
            "Демонстрация структуры отчёта, а не выполненное рецензирование.",
            "Замечание относится к незавершённому демонстрационному проекту, а не к качеству цитируемой публикации.",
        ],
    }
    if chief:
        report.update({
            "scientific_ready": False,
            "ready_for_submission": False,
            "scores": {
                key: {
                    "score": None,
                    "applicable": False,
                    "reason": "Содержательная оценка в этом примере не проводилась; число не присваивается.",
                    "locations": [],
                }
                for key in dimensions
            },
        })
    print(name)
    print(json.dumps(report, ensure_ascii=False, indent=2))
PY
```

Полученные объекты соответствуют `schemas/review.schema.json`, если запуск существует и команда успешно вернула хеши. Они **не проходят gate готовности**: независимость прямо отсутствует, решение требует доработки, имеется открытый blocker, научные размерности не оценены. Не заменяйте `false` на `true`, имя демонстратора на «рецензента», а `major_revision` на `accept` без настоящей работы.

В реальной финальной рецензии все десять размерностей присутствуют. `scientific_validity`, `evidence`, `methods`, `reproducibility` должны быть содержательно оценены для `scientific_ready=true`. При отсутствии корпуса автора `author_style` получает `score=null`, `applicable=false` и объяснение; при непроверенном журнале аналогично `journal_fit`. N/A не превращается в нулевую оценку качества.

## 7. Как превратить ранний пакет в проверенный

1. Выполнить предметный поиск, включая российский фундамент и конкурирующие работы.
2. Прочитать нужные источники/страницы, записать настоящее издание и точные локаторы.
3. Принять решение о включении источников и проверить каждое заявленное утверждение.
4. Построить предметный тезаурус, метод и аргумент; только затем написать рукопись.
5. Выполнить реальную вычитку и инструменты этапа 5 на актуальной версии.
6. Разобрать текущие findings и провести независимые предметную/методологическую рецензии.
7. Получить заключение последнего рецензента на расширенном контексте и собрать пакет runtime.

На любом шаге недоступность материала и неполнота проверки раскрываются. Изменение состояния артефакта должно отражать выполненную работу, а не желание пройти валидатор.
