# MCP: тот же проверяемый движок без shell у host-агента

MCP-сервер предоставляет функции существующего Python-движка. Он не вызывает LLM,
не ищет литературу вместо host-агента и не превращает непроверенный запуск в готовую
статью. Все схемы, хеши, ограничения профиля и отрицательные решения рецензентов
проверяются тем же кодом, который использует CLI.

## Установка и запуск

Из локального checkout репозитория:

```bash
python -m pip install -e '.[mcp,publishing]'
python -m sci_writer.mcp_server --workspace /absolute/path/to/manuscript-runs
```

Установленный console script эквивалентен:

```bash
sci-writer-mcp --workspace /absolute/path/to/manuscript-runs
```

Сервер работает через **stdio**. MCP-клиент запускает его как дочерний процесс;
вывод протокола занимает stdout, ошибки идут в stderr. Для веб-агента нужен host,
который уже умеет подключать MCP-серверы. Сам URL GitHub не предоставляет запущенный
сервер и не даёт веб-чату доступа к файловой системе. Публичного HTTP endpoint и
автоматического облачного развёртывания эта поставка не создаёт.

Пример конфигурации host с поддержкой стандартного `mcpServers` (пути заменить):

```json
{
  "mcpServers": {
    "scientific-writer": {
      "command": "/absolute/path/to/venv/bin/python",
      "args": [
        "-m", "sci_writer.mcp_server",
        "--workspace", "/absolute/path/to/manuscript-runs"
      ]
    }
  }
}
```

Официальный Python SDK изменил высокоуровневый класс с `FastMCP` в v1 на `MCPServer`
в v2. Обёртка явно поддерживает обе ветки: `mcp>=1.28,<3`. Основной импорт —
`mcp.server.MCPServer`, совместимый fallback — `mcp.server.fastmcp.FastMCP`.
Зависимость опциональная: без неё основной CLI продолжает работать, запуск MCP
возвращает понятную ошибку установки. Источники API: [официальная документация](https://py.sdk.modelcontextprotocol.io/),
[руководство миграции](https://github.com/modelcontextprotocol/python-sdk/blob/main/docs/migration.md),
[документация v1](https://py.sdk.modelcontextprotocol.io/v1/), проверено 21.11.2026.

## Инструменты

| Tool | Действие |
|---|---|
| `init_run` | Создать каталог по `run_id`, теме и явным профилям исполнения/рецензирования |
| `next_task` | Вернуть текущий этап, результаты и тексты только относящихся к нему инструкций |
| `status` | Показать актуальность семи этапов и пределы готовности для выбранных профилей |
| `read_artifact` | Прочитать текстовый артефакт и его SHA-256 |
| `write_artifact` | Записать артефакт с проверкой текущего `expected_sha256` |
| `style_profile` | Рассчитать ритм по предоставленным образцам; не выдумывать отсутствующий профиль |
| `freeze_plan` | Зафиксировать локальный хеш плана; это не внешняя пререгистрация |
| `validate_stage` | Проверить конкретный этап или весь запуск |
| `complete_stage` | Закрыть этап только после всех проверок; нужен реальный `actor` |
| `run_quality` | Выполнить локальный линтер и подключённые сервисы, сохранить сырые ответы |
| `hashes` | Получить текущие хеши для отчётов редактора и рецензентов |
| `finalize` | Собрать комплект после седьмого этапа, с дополнительными `formats: ["docx", "tex"]` |
| `export_draft` | Выдать явно незавершённый черновик без повышения готовности |

Шесть инструментов из исходной рекомендации ревью дополнены завершением этапа и
работой с артефактами: без них клиент без shell мог бы смотреть задание, но не мог бы
передать результаты движку. Поиск Crossref/OpenAlex и импорт BibTeX/RIS доступны в
CLI; host также может использовать свои разрешённые исследовательские инструменты
и записать проверенные результаты через `write_artifact`.

## Минимальный цикл клиента

1. Вызвать `init_run` с `run_id`, `topic`, `execution_profile` и `review_mode`.
2. Получить `next_task`; загрузить только этот набор инструкций.
3. Читать и создавать необходимые артефакты. Для изменения существующего файла
   сначала получить `read_artifact.sha256` и передать его в `write_artifact.expected_sha256`.
4. Выполнить `validate_stage`, затем `complete_stage` с фактическим ID сеанса.
5. На этапе 5 вызвать `run_quality`, затем оформить редакторский разбор актуальных
   findings. Не использовать `write_artifact` для имитации ответа внешнего сервиса.
6. После самостоятельных рецензий и последнего заключения главного рецензента вызвать
   `finalize`. Самопроверка допускается только с честными ограничениями соответствующего режима.

## Границы доступа и проверка

`--workspace` — единственная файловая область сервера. `run_id` не принимает пути.
Артефакты читаются внутри конкретного запуска; симлинки не могут вывести за его
пределы. Запрещена запись в `.workflow`, итоговые пакеты и manifest, в том числе
через разрешающийся внутри запуска симлинк-псевдоним. Предел текстового артефакта —
4 МБ. Запись не означает успешной валидации и не закрывает этап.

MCP не добавляет произвольного исполнения shell или Python. Передача текста
удалённому редакторскому сервису сохраняет две явные настройки разрешения из CLI;
импорт отчёта Главреда ограничен путём внутри запуска. Вызов `finalize` не отправляет
статью в журнал.

`tests/test_mcp.py` проверяет настоящий subprocess и JSON-RPC обмен по stdio:
инициализацию, обнаружение tools, создание запуска, выдачу инструкций, валидацию и
отказ преждевременного выпуска. Отдельные тесты проверяют выход за каталог, запись
через симлинк и перезапись с устаревшим хешем. Это проверка транспорта и движка;
ручные UI-сеансы всех сторонних IDE из неё не следуют.
