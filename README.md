# AI Scientific Writer Agent

Система агентов для подготовки русскоязычной научной статьи с опорой на российскую
научную школу, международную литературу, проверяемые доказательства и стиль автора.
Результат — рукопись, библиография, карта источников, редакторские проверки и независимая
итоговая рецензия. Прицел на журналы ВАК и международных баз данных, включая Scopus,
означает адаптацию к конкретному изданию и его требованиям.

**15 ролей · 7 этапов · обязательный этап 5 · главный рецензент — последний агент.**

## Передайте агенту ссылку и тему

```text
Работай по https://github.com/f2re/ai_sci_writer_agent.
Прочитай AGENTS.md и agents/00-coordinator.md, затем веди исследование по этапам.
Тема: <тема>.
Тип статьи: <обзорная / оригинальная / теоретическая / протокол / методическая>.
Целевой журнал или специальность: <если известны>.
Данные и авторские образцы: <пути или приложенные файлы, если есть>.
Сначала сформируй отечественную научную основу и тезаурус, затем сопоставь
с международной литературой. Запроси недостающий авторский корпус и продолжай
исследование с явно обозначенным временным нейтральным стилем.
Обязательно выполни этап 5 и независимые рецензии. Последним работает chief-reviewer.
Выдай статью и полный отчёт; укажи реально выполненные и незавершённые проверки.
```

Агенту нужны чтение репозитория, поиск/доступ к литературе и возможность создавать файлы.
Для независимых рецензий нужны отдельные сеансы агентов или внешние рецензенты.
**Python CLI не вызывает языковую модель:** он выдаёт задания, проверяет контракты,
выполняет реальную инструментальную вычитку и блокирует преждевременную сборку.
Исследование и написание исполняет ваш Codex/Claude/другой host-агент по промптам.

## Быстрый запуск

Требуется Python 3.11+ и checkout всего репозитория. Установка в editable-режиме:

```bash
git clone https://github.com/f2re/ai_sci_writer_agent.git
cd ai_sci_writer_agent
python -m venv .venv
source .venv/bin/activate
python -m pip install -e .
sci-writer doctor
sci-writer init runs/my-article --topic "Тема научного исследования" --article-type review
sci-writer next runs/my-article
```

Инициализация намеренно создаёт **незаполненные** исследовательские артефакты.
Агент заполняет их по результатам реальной работы. Файл задания находится в
`runs/my-article/.workflow/tasks/`. После каждого этапа:

```bash
sci-writer validate runs/my-article --stage 01_intake
sci-writer complete runs/my-article 01_intake --actor intake-session-01
sci-writer status runs/my-article
sci-writer next runs/my-article
```

Чтение веб-страницы с README не всегда даёт агенту доступ к остальным файлам: попросите
его явно прочитать AGENTS, конфигурацию и нужные роли либо клонировать репозиторий.

## Семь этапов

| № | Этап | Проверяемый результат |
|---|---|---|
| 1 | Задание, журнал, стиль | Вопросы исследования, выбранный жанр, реальные ограничения, запрос/профиль авторских образцов |
| 2 | Российская школа и мировой контекст | Фундаментальные труды, карта преемственности и споров, источники, словарь и тезаурус |
| 3 | Доказательства и методы | Атомарные утверждения с локаторами, план анализа, реальные данные/результаты при необходимости, план статьи |
| 4 | Написание | Связная рукопись, где тезисы соотносятся с проверенными источниками и результатами |
| **5** | **Вычитка и проверки нейрослопа** | **Редактура, реально выполненные инструменты, исходные отчёты, решения по каждому замечанию** |
| 6 | Независимые рецензии | Предметная и методологическая критика; исправления возвращают процесс к нужному этапу |
| 7 | Главный рецензент и комплект | Мотивированный вердикт, научная готовность, пригодность к подаче и ограничения |

15 ролей описаны в [каталоге агентов](agents/00-coordinator.md).
Работу обычно ведут 3–4 параллельных исполнителя, переиспользуя роли последовательно.
Писатель работает по разделам внутри одной согласованной аргументации; рецензенты получают
отдельные сеансы и полный комплект доказательств.

## Что обеспечивает российскую научную основу

Отдельный агент ищет фундаментальные отечественные монографии и исследования по заданной
теме. Он фиксирует издание, страницы, условия определения и современный статус положения.
Терминолог строит отношения понятий, русско-английские соответствия и словарь научных связок.
Международный поиск проверяет современность, противоречия и действительные пробелы.
Это не заранее заданный список «обязательных классиков» и не процент российских ссылок.

Профиль автора строится по предоставленным образцам того же жанра. Он учитывает темп,
длину предложений и абзацев, способы формализации и степень категоричности. Без корпуса
система обозначает нейтральный режим и не выставляет выдуманный балл сходства с автором.

Подробности: [научный протокол](docs/scientific-protocol.md),
[контракты и примеры](docs/artifact-examples.md).

## Реальный этап 5 в своём облаке или локально

Запустите собственный LanguageTool. Контейнер работает локально относительно агента;
этот же Compose подходит для вашей облачной VM с Docker.

```bash
docker compose -f deploy/compose.quality.yml up -d
sci-writer quality runs/my-article --languagetool-url http://127.0.0.1:8010
```

Команда создаёт `reports/quality.json` и исходные отчёты с SHA-256. Редактор оформляет
`reports/editorial-review.json`; только после этого возможен `complete ... 05_quality`.
Без доступного сервиса команда сохраняет честный незавершённый отчёт и возвращает код 2.
Удалённый endpoint требует разрешения на передачу текста; бесплатный публичный endpoint
LanguageTool не используется для автоматических запросов по его [официальным правилам](https://dev.languagetool.org/public-http-api.html).

Главред имеет [официальный платный API](https://glvrd.ru/api/). В этой версии реализован
импорт отчёта реальной проверки, поскольку актуальную спецификацию и учётные данные
получают при подключении. Старый сторонний wrapper не считается готовой интеграцией.

```bash
sci-writer quality runs/my-article \
  --languagetool-url http://127.0.0.1:8010 \
  --glavred-report private/glavred-result.json
```

Добавьте `glavred` в `brief.json → quality.required_tools`, если он обязателен в вашем
процессе. Без валидного результата такая проверка блокирует этап. Формат отчёта и
проверенные альтернативы: [каталог 16 инструментов](docs/quality-tools.md),
[развёртывание](deploy/README.md).

Линтеры оценивают текстовые признаки и язык. Они не доказывают происхождение текста.
Статистические AI-детекторы включены в исследовательский каталог как ограниченные
диагностические средства; их балл не является критерием научной готовности.
Автоматическая вычитка всей рукописи v0.1 поддерживает `ru`/`ru-RU`; английская аннотация
проверяется отдельно по требованиям журнала.

## Поиск и доказательства

Встроен небольшой настоящий клиент Crossref для первичного поиска метаданных:

```bash
sci-writer search-crossref runs/my-article \
  --query "точная предметная формулировка" --rows 20
```

Ответ сохраняется в `search/`, запрос — в `search-log.jsonl`. Это **кандидаты**, которые
агент проверяет по первичным источникам, а затем включает в `sources.jsonl`.
Crossref не открывает полный текст и не подтверждает содержание утверждения.
Другие базы и разрешённые библиотечные каталоги подключает host-агент по протоколу.

| Маркер рабочего текста | Значение |
|---|---|
| `[SRC:C001]` | Утверждение прочитанного источника, с точным локатором |
| `[INF:C002]` | Собственный вывод из зарегистрированных утверждений/результатов |
| `[EXP:R001]` | Реальный результат с происхождением данных и журналом выполнения |

Отдельный аудит проверяет поддержку каждого тезиса. Дата публикации и наличие DOI сами
по себе не свидетельствуют о правильности. Работа с закрытыми полными текстами требует
законного доступа; система не обходит ограничения библиотек и издателей.

## Финальная рецензия и выдача

После успешного независимого рецензирования:

```bash
sci-writer hashes runs/my-article
sci-writer validate runs/my-article
sci-writer finalize runs/my-article
```

В `release/` появятся чистая `article.md`, версия с доказательственными маркерами,
`bibliography.bib`, карта цитат, словарь, отчёты проверок, рецензии и манифест хешей.
Полные тексты источников, исходные данные и образцы автора остаются в каталоге запуска;
манифест явно перечисляет такие зависимости. Пакет статьи не подменяет архив исследования.

Главный рецензент оценивает научную состоятельность, новизну, доказательства, методы,
воспроизводимость, отечественную основу, терминологию, читаемость, стиль и соответствие
журналу. Для отсутствующего корпуса автора или неизвестного журнала оценка N/A.
`scientific_ready` отличается от `ready_for_submission`. Содержательная правка делает
старые проверки устаревшими; обновить только хеши вместо новой проверки запрещено.

Если работа ещё не завершена, `sci-writer export-draft runs/my-article` выдаёт явно
помеченную незавершённую рукопись с перечнем препятствий. В журнал ничего не отправляется.

## Проверка реализации

```bash
python -m unittest discover -s tests -v
```

Тесты покрывают отказы сервисов, UTF-16/русскую пунктуацию, неизменность научных терминов,
следы выполнения, устаревшие отчёты и блокировку преждевременной выдачи. HTTP fixtures
в тестах обозначены как fixtures; они не являются доказательством запуска настоящего
LanguageTool. Фактическая проверка облачного запуска описывается в `docs/validation.md`.

Проектное качество контролирует человек. Автоматические проверки подтверждают структуру
и согласованность артефактов; истинность научных выводов и принятие журналом они не гарантируют.
