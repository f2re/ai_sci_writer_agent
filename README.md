# AI Scientific Writer Agent

Система для подготовки русскоязычной научной статьи: российская научная школа,
современная литература, проверяемые доказательства, авторский стиль и итоговая рецензия.
CLI/MCP ведёт состояние и проверяет артефакты; исследование и написание выполняет host-агент.

**8 рабочих модулей + координатор · 7 этапов · обязательный этап 5 · главный рецензент последним.**

В версии 0.2 добавлены ограниченные профили для среды без внешнего сервиса/субагентов,
MCP, издательские метаданные, библиография по настраиваемому профилю, DOCX/LaTeX и импорт литературы.
Полный профиль по умолчанию сохраняет строгие проверки. ВАК, РИНЦ и Scopus означают работу
по требованиям конкретного журнала; система не обещает принятия или автоматической индексации.

Доработка по внешнему ревью: [матрица исправлений](docs/review-resolution.md).
Версия **0.2.1** завершает совместимость с дополнительным руководством:
[обнаружение навыка, publication_meta, выбор библиографии и настройки Claude](docs/guide-resolution.md).
Проверки: [100 локальных тестов и результаты GitHub Actions](docs/validation.md).

## Передайте агенту ссылку и тему

```text
Работай по https://github.com/f2re/ai_sci_writer_agent.
Прочитай AGENTS.md и agents/00-orchestrator.md; загружай модули по sci-writer next.
Тема: <тема>. Тип статьи: <обзорная / оригинальная / теоретическая / протокол / методическая>.
Журнал или специальность: <если известны>. Данные и авторские образцы: <пути / приложения>.
Сначала изучи российскую научную школу и построй тезаурус, сопоставь с мировой литературой.
При отсутствии авторских образцов запроси их и продолжи с явно обозначенным нейтральным стилем.
Выполни обязательный этап 5 и три профиля рецензирования; главный рецензент работает последним.
Выбери режим по реальным возможностям среды. Не объявляй самопроверку независимой рецензией
и пропущенный сервис выполненным. Выдай статью, библиографию, отчёты и точные ограничения.
```

Агенту нужны доступ к файлам и литературе, а для детерминированных gates — CLI или подключённый
MCP-сервер. Чтение только веб-страницы README не заменяет доступ к остальным инструкциям.
Указатели для Claude Code, Gemini CLI, Copilot и Cursor: [совместимость](docs/compatibility.md).
Навыки находятся в `skills/`; загружать весь каталог одновременно не требуется.
Для клиентов с локальным обнаружением есть вход `.agents/skills/sci-writer/SKILL.md`.

## Быстрый запуск

Требуется Python 3.11+ и полный checkout репозитория:

```bash
git clone https://github.com/f2re/ai_sci_writer_agent.git
cd ai_sci_writer_agent
python -m venv .venv
source .venv/bin/activate
python -m pip install -e .
sci-writer doctor
sci-writer init runs/my-article --topic "Тема исследования" --article-type review
sci-writer next runs/my-article
```

Инициализация создаёт незаполненные артефакты, а не демонстрационное «готовое исследование».
Агент выполняет выданное задание, затем закрывает этап:

```bash
sci-writer validate runs/my-article --stage 01_intake
sci-writer complete runs/my-article 01_intake --actor intake-session-01
sci-writer status runs/my-article
sci-writer next runs/my-article
```

Состав исполнителей и выходы каждого этапа определяет только [workflow.json](config/workflow.json).

## Семь этапов

| № | Работа | Проверяемый результат |
|---|---|---|
| 1 | Бриф, издание, автор | Исследовательский вопрос, жанр, ограничения и статус авторского корпуса |
| 2 | Российская школа и мировой контекст | Фундаментальные труды, история понятий, источники, словарь и тезаурус |
| 3 | Доказательства и методы | Тезисы с локаторами, план, данные/результаты при необходимости, аргументация |
| 4 | Рукопись | Связный текст по проверенным основаниям |
| **5** | **Вычитка и проверки нейрослопа** | **Реальные прогоны, исходные отчёты и решения по замечаниям** |
| 6 | Предметная и методологическая проверка | Отдельные рецензии либо явно обозначенные проходы самопроверки |
| 7 | Главный рецензент и выпуск | Вердикт последнего агента, готовность и ограничения; затем сборка |

Восемь модулей содержат функционально связанные задачи. Модуль рецензирования включает три
отдельных профиля; объединение файлов не объединяет независимых рецензентов в одного писателя.
Координатор — дополнительный модуль управления. Обычно достаточно 3–4 параллельных исполнителей.
[Устройство промптов и миграция с 15 ролей](docs/prompt-design.md).

## Российская школа и стиль автора

Отдельный модуль ищет предметные монографии и фундаментальные исследования, фиксирует издание,
локаторы, определения и современный статус положения. Международный поиск проверяет альтернативы
и противоречия. Тезаурус различает эквивалентные и неэквивалентные понятия, русские/английские
соответствия и функции научных связок. Национальная квота не заменяет предметный отбор.

Авторский профиль строится по реальным научным образцам: длины предложений/абзацев, темп
рассуждения, связки и оговорки. Без корпуса система не выдумывает личный стиль или балл сходства.
Подробности: [научный протокол](docs/scientific-protocol.md), [примеры артефактов](docs/artifact-examples.md).

## Полный и ограниченные режимы

По умолчанию `strict_local` + `independent_sessions`: требуются настоящий внешний языковой
инструмент и отдельные рецензенты. Docker — один вариант собственного LanguageTool:

```bash
docker compose -f deploy/compose.quality.yml up -d
sci-writer quality runs/my-article --languagetool-url http://127.0.0.1:8010
```

Можно использовать уже работающий разрешённый сервер или импорт реального отчёта Главреда.
Сохраняются SHA-256, исходные ответы, версии и время. Редактор разбирает каждый актуальный finding.
Удалённый endpoint требует разрешения на передачу текста; бесплатный публичный LanguageTool для
автоматизации не используется. [Каталог 16 инструментов](docs/quality-tools.md), [развёртывание](deploy/README.md).

В среде без сервиса или без отдельных сеансов:

```bash
sci-writer init runs/offline-article --topic "Тема исследования" \
  --execution-profile offline_sandbox --review-mode single_session_self_audit
sci-writer next runs/offline-article
sci-writer quality runs/offline-article
sci-writer readiness runs/offline-article
```

Локальный линтер действительно работает; внешние пропуски обозначаются `skipped_no_runtime`.
Самопроверка выполняет три критических прохода, сохраняя `independent_peer_review=false`.
Ограниченный завершённый цикл выдаёт `reviewed_manuscript` с `scientific_ready=false` и
`ready_for_submission=false`, конкретными limitations и кодами `offline_quality`/`self_audit`.
Научные blocker/major продолжают блокировать приёмку. [Матрица профилей](docs/compatibility.md).

RU-линтер даёт мягкие сигналы о кальках, канцелярите, терминологии и типографике. Для EN-аннотации
есть базовые локальные проверки; это не полная английская редактура. Балл AI-детектора не доказывает
авторство и не является целью переписывания.

## Литература и доказательства

```bash
sci-writer search-crossref runs/my-article --query "предметный запрос" --rows 20
sci-writer search-openalex runs/my-article --query "предметный запрос" --rows 10 --language ru
sci-writer import-bib runs/my-article private/export.bib --format bibtex
sci-writer import-bib runs/my-article private/export.ris --format ris
```

Поиск/импорт создаёт кандидатов и журнал происхождения, а не подтверждённые тезисы. API-ключ OpenAlex
при необходимости передаётся через переменную окружения; метаданные, аннотация и ссылка на PDF
не означают чтение полного текста. Подробности и ограничения парсеров: [литература](docs/literature.md).

| Маркер рукописи | Основание |
|---|---|
| `[SRC:C001]` | Проверенное утверждение прочитанного источника с локатором |
| `[INF:C002]` | Собственный вывод с зависимостями от C/R-ID |
| `[EXP:R001]` | Реальный результат с данными, командой и журналом выполнения |

Реестр хранит точные библиографические сведения, включая журнал, том/номер, страницы,
издание, издателя и идентификаторы при наличии. Доступ к закрытому тексту требует законного основания.

## Издательский блок и выпуск

Сведения RU/EN, авторы/аффилиации, УДК/ГРНТИ/EDN и применимые заявления хранятся в `brief.publication`
(совместимое имя — `brief.publication_meta`, с той же схемой и запретом конфликтующих значений).
Неизвестные значения не выдумываются; обязательность определяется журналом. Библиография имеет
профиль на основе ГОСТ и расширенные BibTeX-поля. Формат экспорта не равен универсальной сертификации.

```bash
python -m pip install -e '.[publishing]'
sci-writer hashes runs/my-article
sci-writer readiness runs/my-article
sci-writer validate runs/my-article
sci-writer finalize runs/my-article --formats docx,tex
```

Для явного выбора оформления доступен `finalize ... --bibliography-style gost|generic`.
Без флага используется стиль брифа. Для готового к подаче выпуска флаг не может менять
уже проверенное оформление: такое изменение требует обновления брифа и повторных проверок.

`release/` содержит article.md, выбранные DOCX/LaTeX, рабочую версию с маркерами, bibliography.bib,
карту цитат, словарь, проверки, рецензии и манифест хешей. Для ещё незавершённого исследования
`export-draft ... --formats docx,tex` сохраняет явный статус черновика и препятствия.
[Издательские поля, ГОСТ-профиль и пределы рендеринга](docs/publishing.md).
Новый комплект собирается изолированно; предыдущий сохраняется в `.workflow/release-history`.
Предупреждения экспортёра не позволяют объявить выбранный пакет готовым к подаче.

Последний рецензент оценивает десять критериев. Без авторских образцов author_style — N/A,
без проверенного журнала journal_fit — N/A. Готовность к подаче не означает принятия журналом.
Данные, полные тексты и образцы остаются в запуске; зависимости перечислены в манифесте.
Содержательные изменения требуют повторных проверок. В журнал система ничего не отправляет.

## MCP без shell у клиента

```bash
python -m pip install -e '.[mcp]'
python -m sci_writer.mcp_server --workspace /absolute/path/to/runs
```

Подключите stdio-процесс на доступной серверной машине. Клиент получает операции над тем же
движком и может читать/создавать артефакты в workspace. [MCP-интерфейс](docs/mcp.md).

## Проверки и исследовательский архив

```bash
python -m unittest discover -s tests -v
```

Проверки охватывают происхождение доказательств, ложный успех сервисов, устаревшие отчёты,
режимы готовности, библиографию/экспорт и новые интерфейсы. Реальные прогоны описаны в
[validation.md](docs/validation.md); fixtures не выдаются за настоящее исследование или сервис.

[Исторический архив](research-archive/README.md) содержит аудит 10 веток исходного проекта,
обзор внешних систем и журналы источников. Он исключён из обычного контекста написания статьи.
Автоматическая проверка структуры и согласованности не заменяет ответственность автора за содержание.
